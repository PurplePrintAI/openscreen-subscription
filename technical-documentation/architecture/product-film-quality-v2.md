# PurplePrint 제품 소개 영상 — 품질 개선 v2

2026-10-11 · Studio 소비자 측 제안. **데모·투어 자동화 연동 규격은 아직 Claude 측과 합의되지 않았다.** 기존 개발 브랜치 `feat/product-demo-production`에 HyperFrames 로컬 렌더 어댑터를 추가했다. 사용자가 제공한 배포 데모를 실제 조작해 촬영했고, 문서 패널을 촬영 전에 넓힌 화면 초안과 두 음성 비교 샘플을 만들었다. 전체 소개 영상의 성장·인계·마무리 장면과 음성 승인은 남아 있다. [현재 검증 범위](../testing/narration-2026-10-11.md).

## 1. 사용자 피드백과 확인한 현황

요청은 5분 미만의 **실제 제품 기능과 가치**를 보여주는 소개 영상이다. 이전 2분 10초 초안은 랜딩페이지를 촬영한 것이므로 촬영·편집 파이프라인의 검증 결과로만 남긴다. 이후 영상의 주요 소스로 다시 사용하지 않는다.

확인 범위:

- 최초 조사 시 Studio에 HyperFrames 연결이 없었다. 이후 사용자 승인에 따라 현재 작업 브랜치에 로컬 연결을 구현했다. `.12` 설치본 및 릴리스에는 포함되지 않았다.
- 로컬 `D:/dev/engine-plugins/brand-film-video-engine` 0.1.0은 장면·키프레임·오버레이·프롬프트 기획 엔진이다. HyperFrames 렌더러가 들어 있는 것은 아니다.
- `cinematic-knowledge-shorts-engine` 0.3.0에는 주장/출처 관리, 음성 길이에 따른 장면 계획, 생성 작업, FFmpeg 조립과 품질 검수 방법이 있다. 제품 소개에 필요한 방법을 재사용하되, 숏폼 서사나 세로 비율을 강제하지 않는다.
- Claude 소유의 `D:/purpleprint-worktrees/first-experience`에서 10월 11일 데모·투어 인계 문서와 HTML 시안을 확인했다. 설계 코치 8걸음, Hyper-Review 8걸음, 내 성장 7걸음, 다음 행동 1걸음이다. 인계 문서상 시안은 승인됐고 S3 제품 구현 및 익명화된 데모 사본 생성은 다음 작업으로 기록돼 있다. **실제 공개 완료로 취급하지 않는다.**

자료 위치는 읽기 전용 참고다. Studio 작업에서 MCP, 웹 코치, 데모 원본 계정, 투어 코드를 수정하거나 사본을 임의로 생성하지 않는다. 다른 엔진의 소스도 배포 조건 검토 없이 이 공개 포크로 복사하지 않는다.

## 2. 역할과 제작 흐름

```text
Claude: 실제 결과물이 있는 데모 프로젝트 + 제품 투어 + 익명화/읽기 전용 보장
    ↓ 공개 가능한 데모 URL, 투어 단계 식별자, 실제 화면 근거
Studio: 투어에 맞춘 제품 촬영 + 기다림 제거 + 화면 상세 확대
    ↓ 원본 take, 장면별 의미와 초점, 길이/음성 기준
HyperFrames: 브랜드 타이틀·장 전환·설명 도형·강조·모션 합성
    ↓ 렌더 클립 + HTML/설정 원본
Studio: 타임라인 조립·자막·음성·검수·MP4 초안
```

HyperFrames는 실제 웹앱을 탐색하거나 제품 상태를 준비하는 촬영 도구의 대체물이 아니다. 이번 역할은 확보한 제품 화면과 설명 요소를 일정한 시간축으로 합성하는 것이다. 생성 모델로 제품 UI나 점검 결과를 새로 그려 실제 기능처럼 보여주지 않는다.

## 3. 내용과 연출

**사용자 추가 기준(2026-10-11):** eyebrow, `PILOT`, 장식용 단계 번호 등
제품에 없는 상단 라벨을 영상에 덧붙이지 않는다. 현재 PurplePrint 제품의
톤앤매너(실제 서체·표면·간격·보라색의 의미)를 유지한다. 기본은 제품 화면이
프레임을 채우는 실제 조작 녹화이며, 별도 네온 배경이나 임의 마케팅 카드를
추가하지 않는다. 화면 캡처에 모션을 준 시안을 실시간 녹화로 대체했다고
설명하지 않는다. 촬영을 위해 제품 코드를 수정하거나 데모 데이터를 고치지 않는다.

투어 24걸음은 방문자가 상세히 탐색하는 안내다. 소개 영상에서는 이를 가치 중심 10~14개 장면으로 묶는 안을 제안한다. 3분 안팎을 목표로 하고 5분 제한을 유지한다. 음성 제작 시 실제 발화 길이에 맞춰 최종 시간을 조절한다.

| 구간 | 전달할 가치 | 반드시 보여줄 제품 근거 |
|---|---|---|
| 도입 | 무엇을 만들어야 할지 막막한 출발점 | 짧은 제목 뒤 바로 실제 제품 작업 공간 |
| 설계 코치 | 판단을 혼자 시작하지 않아도 됨 | 추천과 이유 → 결정 카드 → 승인한 내용이 문서로 연결되는 흐름 |
| 설계의 결과 | 대화가 다음 작업에 쓸 수 있는 자료로 남음 | 문서 역할, 진행 상태, 클릭 가능한 시안 |
| Hyper-Review | 그럴듯한 결과를 근거로 다시 검토함 | 실제 리포트의 정체성/구조/발견 근거/다음 행동 중 핵심 구간 |
| 내 성장 | 사용자가 AI를 이끄는 방식도 돌아볼 수 있음 | 실제 성장 기록과 관측된 행동, 다음 연습 |
| 다음 행동 | 설계 이후 자기 도구에서 계속 작업함 | 인계 문서·과업 목록·지원하는 연결 경로 |

연출 기준:

- 한 장면에 하나의 핵심 행동과 결과. 모든 화면을 10~16초씩 정지해서 나열하는 방식을 기본으로 삼지 않는다.
- 전체 작업 공간으로 위치를 알려준 뒤, 읽어야 할 카드·문서·리포트 부분을 확대한다. 좌우 분할은 원인과 결과를 함께 보여줄 때만 쓴다.
- 투어 설명 카드와 영상 자막이 같은 내용을 중복 설명하지 않도록 한다. 촬영 중 투어 안내를 숨기는 기능이 필요하면 Claude 측 지원 여부를 먼저 합의한다. 제품 결과나 수치를 숨기거나 바꾸는 용도로 쓰지 않는다.
- PurplePrint/graphOS의 실제 색·서체·간격·브랜드 자산을 영상용 기준으로 정리한다. 임의의 네온 효과나 과도한 3D 전환으로 제품 가독성을 낮추지 않는다.
- 내레이션과 자막을 기준으로 컷을 잡고, 음악·효과음은 설명보다 낮게 둔다. 목소리와 음원은 사용 조건을 확인한 뒤 선택한다.
- 클릭·호버·스크롤은 의도를 보여줄 만큼만 남긴다. 대기 구간은 편집하되 실제 처리 시간을 실시간인 것처럼 오인시키지 않는다.
- 고정 데모에서 재생한 결과, 실제 실시간 실행, 설명용 모션을 제작 메타데이터에서 구분한다. 샘플 수치가 최종 데모 사본의 수치와 다른 경우 대본을 다시 검수한다.

## 4. 촬영 품질의 별도 개선

현재 방식은 720p 브라우저 프레임을 최대 12fps로 모은다. 이를 30/60fps로 인코딩하거나 HyperFrames에 넣는 것만으로 원본 움직임이 부드러워지지 않는다.

다음 촬영 경로는 **실제 1080p, 최소 30fps 수집**을 목표로 별도 검증한다. Studio의 기존 네이티브 창 녹화 경로를 우선 검토하고, 대상은 Studio가 소유한 제품 창 하나로 고정한다. 프레임 누락, 글자 선명도, 스크롤·커서 움직임을 확인한 뒤 채택한다. 아직 달성된 성능이 아니다.

투어 시안에 이미 있는 대상 안정화 원칙(모드·탭·스크롤 종료 뒤 위치가 연속 프레임에서 안정됨)을 재사용하는 것이 좋다. 단순 고정 sleep 대신 투어 준비 상태를 기다린다. 준비 신호가 없으면 실패를 표시하고 해당 장면만 다시 촬영한다.

## 5. Claude 측 산출물에서 받을 항목 — 제안

별도 메시지는 아직 보내지 않았다. 다음은 Studio 소비자가 필요로 하는 정보이며 서버 API를 일방적으로 확정하는 문서가 아니다.

1. 공개 가능한 읽기 전용 데모 URL과 데모 판 번호. 계정 이름·비공개 자료 제거 여부.
2. 네 장의 단계 목록: 안정적인 단계 ID, 제목, 전달 가치, 근거가 되는 문서/화면. `#step=번호`는 현재 시안 주소 규칙일 뿐 운영 계약으로 하드코딩하지 않는다.
3. 각 단계로 이동하는 지원 방식과 준비 완료 신호. 가능하면 기존 `data-tour` 식별자를 사용한다.
4. 초점 영역: 대상의 좌표, 좌표계, viewport, 보이는 범위. 다른 출처의 리포트는 Claude가 설계한 `postMessage` 경계를 존중하고 DOM 접근을 우회하지 않는다.
5. 각 단계의 내용이 실제 결과물/샘플/설명 시안 중 무엇인지, 영상에 사용할 수 있는지.
6. 투어 카드 숨김, 초기 상태 재설정, 종료 방식의 지원 여부. 없는 동작은 Studio가 있다고 가정하지 않는다.

Studio 쪽에서는 이 데이터를 녹화 순서와 영상 장면 계획으로 변환하는 어댑터를 만든다. API의 출처·송신 창·요청 ID를 확인하고 제한된 단계 이동 명령만 처리한다. 일반 페이지의 설명문이나 임의의 스크립트를 실행 명령으로 사용하지 않는다.

## 6. HyperFrames 연결 방식 — 로컬 개발 연결 구현

[공식 개발 문서](https://hyperframes.heygen.com/developers)는 프로젝트 단위 자동화에는 CLI부터 연결하고, 필요할 때 SDK와 Player를 더하는 방식을 안내한다. [프로젝트 모델](https://hyperframes.heygen.com/concepts)은 HTML과 미디어, 장면 시간축을 원본으로 유지한다.

Studio는 **HyperFrames 0.8.146 / GSAP 3.14.2**를 별도 npm 런타임에 고정했다. 기본 편집기 전체를 교체하거나 클라우드 업로드를 도입하지 않는다. 입력은 등록된 프로젝트의 영상 자산과 장면 설정, 출력은 렌더 영상·포스터·렌더 진단·원본 프로젝트 경로다. 설치·CLI 옵션과 환경 변수는 실제 설치된 버전에서 확인했다. [로컬 설치와 사용](../../tools/hyperframes/README.md).

처음에는 완성된 모션 클립을 기존 Studio 영상 자산으로 가져온다. 이 경우 모션 안의 글자를 Studio 텍스트 도구로 직접 수정할 수 있는 것은 아니다. HTML·변수·렌더 판 번호를 함께 보관하고, **원본 수정 → 해당 장면 재렌더 → 클립 교체**가 가능해야 한다. 실시간 HTML 편집기 통합은 이후 별도 범위다.

## 7. 다음 구현 순서와 완료 판정

1. **투어 입력 연결:** 실제 데모 URL과 단계 데이터가 준비되면 제목 검색 대신 단계 ID로 원하는 제품 상태에 도달하고, 기존 데모를 변경하지 않는지 확인.
2. **대표 15~20초 장면:** ‘추천 → 결정 → 문서’ 한 구간을 고해상도 촬영하고, HyperFrames로 강조·전환·브랜드 표현을 더한다. 먼저 이 한 장면으로 품질 방향을 검토한다.
3. **전체 확장:** 대표 장면 수준으로 코치·점검·성장·인계를 연결하고 음성에 맞춰 3분 안팎으로 구성. 일부 장면 실패는 해당 장면만 재작업.
4. **검수:** 실제 제품 화면과 주장 대조, 한글 잘림/최종 크기 가독성, 음성·자막 싱크, 음악 밸런스, 실수집 fps, 5분 미만, 원본 수정·재렌더, Studio 프로젝트 재열기·내보내기.

후속 설치 작업에서는 로컬 런타임과 Studio 연결을 구현하고 진단용 장면으로 검증했다. Claude의 제품·데모·투어 코드는 변경하지 않았으며 실제 제품 재촬영, 유료 생성, 릴리스 배포는 하지 않았다. 데모·투어가 준비되기 전에 랜딩페이지 영상에 효과만 더해 최종 제품 소개라고 부르지 않는다.
