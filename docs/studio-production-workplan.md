## 컴퓨터 유즈 종료 기록 정정 — 2026-10-14

사용자가 컴퓨터 유즈를 매번 수동으로 종료하고 있었다고 알려주었다.
이 문서와 앞선 QA 기록의 ‘컴퓨터 유즈 종료’는 실제로 **QA 앱 종료와 Node REPL
초기화까지만 확인한 것**이다. `js_reset`은 JavaScript 런타임 초기화이며,
Windows 컴퓨터 유즈 세션 종료·사용자에게 제어권 반환을 증명하지 않는다.
기존 종료 완료 보고는 잘못됐으며, 사용자 수동 종료가 필요했던 사실을 반영한다.

향후 QA 앱 종료 / 입력 중지 / 런타임 초기화 / 컴퓨터 유즈 세션 종료를 구분한다.
실제 세션 종료 방법과 확인 수단을 확보하기 전에는 종료 완료를 주장하지 않는다.
이 문제가 해결되거나 사용자가 이 제약을 알고 다시 허용하기 전까지 화면 조작을
자동으로 재개하지 않는다. 코드·파일·테스트 작업은 화면 조작 없이 진행할 수 있다.

## 현재 단계의 범위

기획 화면의 `장면 구성 / AI 기획 / 장면 시트 / 애니매틱 / 수정·검수`에서 같은 기획을 사용한다.
애니매틱은 `assembleScenePlan → AxcutDocument → buildSceneDescription`을 사용하며,
편집기의 전역 프로젝트나 플레이헤드를 임시로 바꾸지 않는다. 네이티브 합성기를
사용할 수 없으면 이를 명시하고 원본 영상 미리보기로 조용히 대체하지 않는다.

기획 수정은 프리뷰의 재생을 멈추고 새 장면 상태로 반영한다. 재생·일시정지·탐색과
장면별 이동을 제공한다. 저장된 나레이션은 선택한 경우에만 재사용하며 생성 호출은
추가하지 않는다. 컷 경계는 기존 조립의 하드 컷이며 새 디졸브나 생성형 전환은 제외한다.

변경 전 작업 파일을 별도 스냅샷으로 보존한다. 검증은 기존 승인 자료의 19초 세 장면을
사용하며, 한글 자막·줌·컷 경계·수정 반영·탭 종료·재진입을 확인한다. 단위 테스트를
통과해도 네이티브 화면과 출력 일치를 검증한 것으로 처리하지 않는다.

## 작업과 검수 절차

1. 기준본 보존과 영향 범위 확인.
2. 데이터·재생 수명 관리 구현, 오류·빠른 탐색·오래된 비동기 응답 테스트.
3. 한국어 UI와 타입·관련 회귀 테스트, 마지막 전체 테스트와 빌드.
4. 격리 QA 앱에서 실제 화면 확인과 필요한 출력 프레임 비교.
5. QA 앱·컴퓨터 유즈 즉시 종료, 결과와 남은 한계를 기록.

실제 사용자 프로필, 개인 음성 원본, 인증 정보, 클라우드 업로드, Kling 제출,
공개 릴리즈 및 설치본 교체는 이번 단계에 포함하지 않는다.
